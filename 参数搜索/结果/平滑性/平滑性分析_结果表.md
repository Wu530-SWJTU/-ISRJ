# 三维平滑性分析（θ = [t_0, d, T_s]）

设计对：`joint_design_result_t0_2.5us.npz`（t_0 = 2.5 μs、T_s = 10 μs、T_L = 2.5 μs）。把「参数估偏了，抗干扰性能掉多少」这张曲面，按搜索算法关心的角度体检一遍。

## 一句话结论

- **t_0（转发时间）与 T_s（采样周期）——规矩、好搜**：偏离后性能平滑变差，每挪一个采样点方向基本都对，可以直接用爬山法 / 梯度法。
- **d（占空比）——又粗又乱，不能细搜，也不能靠「找最低点」来估**：每挪一个采样点，四步里就有一步方向是反的；而且它单调（窗口越窄越好），最低点永远落在边界上。

## 一、参数最小能调到多细？

- 把误差一点一点加大（每步只有 0.0049 个采样点），**99.5% 的调整，电平毫无变化**，只在新跨过一整个采样点时才跳一下。
- 最小有效步长 = **1 个采样点**：t_0、T_s 是 0.05 μs，d 是 0.005。
- 含义：调得比这更细等于白调——程序读到的电平一模一样（这不是精度问题，是量化）。

## 二、偏离之后，性能掉得顺不顺？

| 方向 | 每挪 1 个采样点，电平平均动多少 | 单步最大跳变 |
|---|---|---|
| t_0 | 0.56 dB | 1.80 dB |
| T_s | 0.73 dB | 2.60 dB |
| d | 0.48 dB | 1.76 dB |

坡度本身的变化也不超过 1.33 dB/采样点²，没有突然变陡的悬崖。
含义：**只要步长 ≥ 1 个采样点，这张曲面就是「平滑可爬」的**，不会一步踩空。

## 三、往哪边挪是对的？（最要紧的一条）

| 方向 | 连挪 40 步，方向反了几步 | 判读 |
|---|---|---|
| t_0 | 1 / 40（2%） | 方向可靠，蒙着眼爬也对 |
| T_s | 1 / 40（2%） | 方向可靠 |
| d | **10 / 40（25%）** | 四步里就有一步爬错方向 |

为什么 d 这么乱：电平对 d 的响应，取决于「多采样 / 少采样那一个采样点」的正负号，而这个符号基本是随机的。所以 d 那点「越窄越好」的单调趋势只是统计平均，单步看完全没有规律。

## 四、谷底是一个点，还是一条沟？

- 在 11×11×11 = 1331 个网格点上找「四面都比我高」的最低点：**一个都找不到（0 个）**。
- 原因：t_0、T_s 两个方向都是两边变差（真谷底），但 d 方向单调——窗口越窄越好，所以「最低点」只会被推到 d 能取的最小值（边界）上。
- 含义：**别用「找最低点」来估 d**（答案永远是「干扰越弱越好」）；估 t_0、T_s 才成立。

## 五、谷底是尖角还是圆碗？

- 是**尖角**（像 V 字的底），不是圆碗底。
- 后果：用「左右对称取两点估斜率」这种常规做法，会把 d 这种「一直朝一边降」的方向误判成「这里就是最低点」——Hessian 三个特征值全为正就是这么来的。
- 做法：判断是不是谷底，要**左右两边分开看**，不能只看对称差分。

## 六、给搜索算法的四条硬约束

1. 步长 ≥ 1 个采样点（t_0 / T_s 用 0.05 μs，d 用 0.005），比这更小毫无意义；
2. d 维**不要**用单采样点步长的爬山 / 坐标下降——要么用粗步长（≥ 5~10 个采样点），要么先对若干采样点平滑再判方向；
3. t_0、T_s 两维可以放心用梯度 / 爬山类方法；
4. 估 d 不能拿「让电平最低」当目标（会一路推到边界），得换判据（如相对自身能量的抑制比）。
